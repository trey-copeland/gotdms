# DAQmx raw data

[Back to the docs index](README.md)

**DAQmx raw data is decoded for the layouts NI hardware writes, and rejected otherwise.** A channel whose raw-data index is one of the three words below is read as DAQmx data. The index words decide the layout, as in npTDMS: a segment whose table-of-contents has `kTocDAQmxRawData` (bit `0x80`), including a file whose first segment sets that bit, is read whether its channels use DAQmx or standard indexes. No real NI DAQmx file is checked in; the layouts are checked against npTDMS-built files in CI. `Values`, `Slice`, `Cursor`, `ReadValues`, and `Float64s` return the primary scaler's raw samples in its native type (`int8` through `float64`, and `Timestamp`). A digital-line scaler returns `[]uint8` of 0 and 1. Nothing is scaled unless the caller uses `DAQmxScaledFloat64s` or `ApplyDAQmxScale`.

Supported index words, as a little-endian `uint32`:

- `0x00001269` and `0x00001369` are format-changing scalers. Each scaler is five `uint32` fields: DAQmx data type, raw buffer index, byte offset, sample-format bitmap, scale id. The NI article calls `0x00001369` a digital-line scaler. npTDMS does not accept that word, and no NI file here uses it. This package assumes the format-changing layout for it; a record of another shape fails the bounds checks.
- `0x0000126A` is the digital-line scaler used by NI DAQ files. The fields are three `uint32` values (type, raw buffer index, bit offset), one bitmap byte, and a `uint32` scale id. Bit 0 is the least significant bit of byte 0 of the stride.

The raw section is one or more raw buffers concatenated in each chunk. A buffer's stride is its raw-data width. Channels that share a buffer are interleaved at their byte offsets. Buffers may contain different numbers of samples. The data-type word inside the index is `0xFFFFFFFF`, or the one scaler's own type. The sample-format bitmap must be 0. Raw buffer widths and byte offsets may change between segments, for example when a later acquisition adds a channel; the scaler count, scale ids, and types may not.

Still `ErrDAQmx`: a non-zero bitmap, a data-type word that is neither `0xFFFFFFFF` nor the one scaler's type, an unknown DAQmx type code, a digital scaler whose type is not an integer, a raw buffer no scaler references, a segment that mixes DAQmx and standard channels, and a standard index whose type field is `0xFFFFFFFF`. A channel cannot change between a standard index and a DAQmx index. Thermocouple, RTD, table, strain, and add/subtract scales stay visible as properties and are not applied. This package does not write DAQmx raw data.

## Format choices

**DAQmx.** The format-changing scaler index is the bytes `69 12 00 00`, little-endian `0x00001269` (decimal 4713, the same number as the version, in a different field). `69 13 00 00` (`0x00001369`) is the same five-field scaler. The NI article calls `0x00001369` a digital-line scaler; the digital-line layout in NI DAQ files is `6A 12 00 00` (`0x0000126A`), three `uint32` fields, one bitmap byte, and a scale id. There is no `0x12C9` (decimal 4809) in the article. The raw-data index is not a length-prefixed standard index: the first word is the marker, then data type `0xFFFFFFFF` (or the one scaler's type), dimension 1, chunk size, the scaler vector, and the raw-data width vector. Within a chunk the raw buffers are concatenated. A buffer holds `(samples in that buffer) * width` bytes, and a channel's value starts at its byte offset in each stride. A digital scaler's offset is a bit index. Reads return those raw values. `DAQmxScaledFloat64s` and `ApplyDAQmxScale` apply a linear or polynomial chain (`y = slope*x + intercept`, or `y = sum(coeff[j] * x^j)`). The output is the last scale, index `NI_Number_Of_Scales - 1` (or the highest typed index when that property is absent). A count of 0 applies nothing. Each scale reads its input source, as npTDMS computes it. An index with no `NI_Scale[i]_Scale_Type` is the DAQmx scaler whose scale id is `i`, so an input source of 0 with no `NI_Scale[0]` reads scaler 0 (the article's linear example). Input `0xFFFFFFFF` is the primary scaler. Status `scaled` means the stored samples are already engineering units, so `DAQmxScaledFloat64s` returns the raw float64 values.

The support-matrix row is in [Format](format.md#support). The DAQmx calls (`Channel.DAQmx`, `DAQmxSlice`, `DAQmxScaling`, `DAQmxScaledFloat64s`, `ApplyDAQmxScale`) are listed in [API](api.md).
